# Changelog

All notable changes to Skywrite are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 1.0.0 - Unreleased

### Added

- First public release of Skywrite, licensed under MIT, copyright 2026 FlyCockpit LLC.
- JSON-first media inspection, frame sampling and optional OpenRouter analysis and transcription with word timestamps.
- Multi-recording synchronization by audio waveform or transcript, with drift estimates and quality reporting; `strong` needs method-level residuals (`strong_p95_limit_seconds`: 5 ms for waveform, 50 ms for transcripts), and mappings are reported without float noise (an exact match is `scale` 1.0).
- `skywrite sync apply` places a sync result into an edit (frame-grid start, sub-frame `source_in`, drift `speed`, duration trimmed to the real overlap, reference sound muted), refuses results that are not `strong` with drift estimated unless `--allow-limited`, reports `uncovered` timeline, and with `--verify` renders and re-syncs each placed clip. Audio sync measures pre-emphasized waveform anchors every 2 s across the overlap (at most 1800) with sub-sample peak interpolation, and reports takes that one mapping cannot fit (a cut, dropout or recorder restart) as `discontinuous` with located `segments` (each stopping 0.3 s short of a boundary); sound inside a matched stretch that fits no mapping makes the result `limited`; anchors carry their `segment`; `candidate_matches` counts waveform probe windows.
- Edit JSON format version 1, with validation, lint and review tools and a native FFmpeg MP4 renderer. Clip audio is sample-exact at speed 1 and at clock-drift speeds within 0.1% of 1 (resampled); larger speed changes keep pitch with `--stretcher auto|rubberband|atempo` (default `auto`: FFmpeg `rubberband`, latency-compensated by a per-speed calibration to within about 6 ms (8 ms at 0.125x), falling back to `atempo` with a warning when FFmpeg lacks it). The same applies to `audio tempo` and exported FFmpeg scripts.
- Required transcript content fingerprints for transcript-based caption tracks, `describe frames --transcript` and `review lint --transcript`, matching analysis and edit suggestions; byte-identical media copies are accepted, and media SHA-256 hashes are cached locally.
- Export to FCPXML, Premiere XML (xmeml), Hyperframes, Remotion and FFmpeg scripts; import Premiere/FCP 7 XML and experimental `.prproj` files.
- Remotion exports pin `remotion` and `@remotion/cli` 4.0.546, whose own zod pin (4.6.7) carries the GHSA-mrhx-c7xc-m3w5 fix, so the project needs no `overrides` and Remotion prints no version-mismatch warning.
- Exact-timing evidence (`inspect --exact-audio`, `verify`) names its decoder compactly as `decoder: {ffmpeg_version, build_sha256}`, the hash covering the whole `ffmpeg -version` output, instead of embedding that banner; timing evidence is `version` 2 under `audio-timing-v2`.
- Premiere XML fits each video clip to the sequence with a Basic Motion Scale (omitted at exactly 100%), as the renderer does for square-pixel sources, using the displayed size of rotated phone footage; `inspect` reports a video stream's display `rotation`, and `review lint`, `review sheet` tiles, `describe` frame and video sizes and `verify --expected-width/--expected-height` use the displayed size.
- Premiere XML import was checked in Premiere Pro 26.5.2 on macOS 26.3.1 (audio tracks, levels and fades, 23.976 timing, `--media-root` links, Time Remap speed); the export note now says what that check covered and what it did not (captions, opacity keyframes, the fit Scale, other effects and versions).
- `review lint` reports `brief_shot` for a take, or black between full-frame pictures, on screen for less than `--min-shot-seconds` (default 0.5, 0 to 10) between two hard cuts, catching flash frames such as a speaker showing for a few frames between B-roll clips, short overlays and titles (also at partial opacity), and black gaps between pictures that fill the frame to the pixel as the renderer fits them; its length is exact on the edit's frame grid, the timeline's ends counting as hard cuts. Fades and dissolves are not checked yet, and black gaps are checked only between full-frame pictures: a stretch with a fade, dissolve or opacity change at either edge, or black next to letterbox bars, a picture-in-picture, an opaque logo or a partial-opacity picture, is never reported, and when it is under the threshold it is listed in `checked.brief_shots_not_checked` and counted in `not_checked`. Only a certainly opaque full-frame picture counts as cover (stills sized as FFmpeg decodes them, after any EXIF rotation), for this check and the silent-speaker check: video whose pixel format has no alpha channel, or a still whose decoded pixels are all opaque (`checked.uncertain_cover_sources` lists pictures that cannot be judged); `inspect` reports each video stream's `pix_fmt`.
- `edit export --media-root FOLDER` writes FCPXML and Premiere XML media URLs beneath the editor's folder, so exports made on another machine (for example in the cloud) link on open.
- Native HTML or JSON still graphics through embedded Takumi, with PNG, JPEG and WebP output.
- Optional image, video, narration and music generation and upscaling through OpenRouter, with durable generation projects and optional S3/R2 uploads.
- Generation exit contract: `generate`, `upscale video` and `jobs resume` exit 0 only for a completed or still-running job; other end states exit 1 with `{"error":{"code","message","job"}}` (`not_sent`, `job_not_submitted`, `job_uncertain`, `job_received`, `job_rejected`, `job_failed`). A submission whose connection failed before any byte was sent returns the job to `prepared` ("nothing was billed, rerun the same command") instead of leaving it uncertain; split narration sections and project nodes follow it. Nothing is retried automatically.
- `audio duck` (and `finish --sidechain`) ducks the same way on every run: both inputs reach `sidechaincompress` in fixed 1024-sample frames. On FFmpeg 7.0 and later the frame split followed thread timing, so the ducked music could differ between runs near a change in the narration (measured: 2 to 6 different results in 8 runs on 7.0.2 through 9.1; with the fix, one result on every build from 5.1.2 to 9.1 for the same music and narration).
- Edit renders, exported FFmpeg scripts and crossfaded audio loops (`audio loop`, `finish --loop`, `roomtone` beds) give the same result on FFmpeg 5.1.2, 6.1.1, 7.0.2, 7.1, 7.1.1, 8.0.1, 8.1.2 and 9.1 (docs/validation.md). A clip whose video starts after its audio gets its black lead-in after the frame-rate conversion; FFmpeg 7.0 and 7.1 `setpts` clears the frame rate that `tpad` needs, which had left the lead out. Loops sum faded, delayed copies instead of chaining `acrossfade`, which before FFmpeg 8.0 could end a loop of a short cue early and pad the rest with silence.
- Renders and exported FFmpeg scripts put every clip on exactly the frames the edit's grid gives it. Each track is retimed on the output frame clock (frame N at N/fps) after its clips and gaps are joined, so no rounding is left. Before, the joined track carried microsecond timestamps and per-segment end times. The measured effects (docs/validation.md):
  - At 29.97 fps the clip after a cut started one frame late, so a 2-frame shot showed 3 frames and a 14-frame shot 15.
  - At 23.976 fps clips started early and the last frames of the edit were black.
  - At 25 and 30 fps a one-frame clip after a gap vanished and later clips moved a frame.
- Within each clip, a rendered frame shows the source frame on screen at its source time (`source_in + n × speed / fps`, the last frame starting at or before it), as an NLE does, so the picture stays with the sound. This applies to renders and exported FFmpeg scripts. Before, FFmpeg `fps` sampling from the first frame at or after `source_in` could show a frame ahead of the source time: up to a source frame plus half an output frame, and more at high speeds or with coarse timestamps. How it works:
  - The picture decode starts 1 s before `source_in`, or at the start of the picture on screen then if that is earlier (variable frame rate).
  - A video stream that starts after `source_in` gets a whole number of black frames before its first picture.
  - Frames whose container rounded their times (Matroska stores 29.97 or 30 fps to 1 ms) are read on the nominal frame grid when they lie within that rounding of it (docs/edit-format.md, docs/validation.md).
  - Clip sound, for video and audio-only clips, is decoded from the same earlier point and trimmed at `source_in` on the file's own timeline, wherever the decode resumes. It is sample-exact, or within half a millisecond for Matroska, which stores times to 1 ms.
- The whole test suite passes on each of those FFmpeg builds. Rubberband's input is padded before the clip with the clip's own first samples reversed (a clip shorter than the pad looped first) instead of silence, so stretched clip audio no longer starts after an artificial onset, which had made the first 150 ms of pink noise 3.5 dB quiet on every version and a steady tone 15 dB quiet for 150 ms (static 5.1.2–7.1.1) or the whole clip (static 8.0.1, 8.1.2). Pure tones keep a limit: a short pure-tone clip sped up (0.8x and faster) can still come out 2–9 dB low depending on the phase at the cut, and a pure tone after digital silence inside a clip up to 15 dB low (docs/validation.md). MP4/MOV durations come from the audio and video streams' start and duration, so FFmpeg 5.1, which reports a 3-s MP4 starting at 5 s as 8 s long, no longer admits source ranges past the end. `sync apply` no longer drops a placement when the offset lies within the frame-grid snap of a frame boundary (an FFmpeg 9.1 decode measured 18.000000004 s and got "does not overlap").
- `skywrite audio roomtone SPEECH --bed ROOM -o OUT`: dry speech loudness-normalized first (`--lufs`, default -18), a room-tone bed resampled, optionally high-passed (`--bed-highpass`), set to a measured target level (`--bed-dbfs`, default -58 dBFS RMS), looped with equal-power crossfades or trimmed, summed with `amix normalize=0` and no later loudness pass; output length equals the speech. Unusable beds (missing, silent, too loud, too quiet, under 1 s) are refused; the JSON report has the measured speech, bed and mix levels.
- `skywrite audio inputs` lists capture devices through the system FFmpeg (PulseAudio/PipeWire, ALSA, macOS avfoundation, Windows dshow) without recording. `skywrite audio record-bed --seconds N -o bed.wav --confirm` records room tone only with explicit consent: mono 48-kHz PCM16, a measured 4-s start-up lead discarded, never uploaded, with level, hum share, crest factor, transient and speech-likeness measurements and warnings, and macOS permission problems explained.
- `describe frames` and `describe video` take `--focus TEXT` (repeatable), `--focus-file` and `--focus-schema FILE`: the agent says what it needs from each frame or clip, and the answer is returned under `focus` (`instructions_sha256`, `schema_sha256`, `answer`) beside the unchanged general description. Schemas use a documented JSON Schema subset with `"x-skywrite": "box"`/`"point"` for normalized coordinates (0..1 of the full upright frame, origin top-left, boxes `[x1, y1, x2, y2]`; model estimates, range- and order-checked, clamped within 0.02; numbers compare as IEEE-754 doubles (whole numbers exactly), and schema numbers must be 64-bit integers or floats that are 0 or between 2^-1022 and 2^53 in magnitude). A valid description or answer that cannot be written to the cache is returned with `cache_error`. A mismatch gets one corrective retry (the answer then reports `first_attempt_errors`), then a typed per-frame failure (`focus_schema_mismatch`, `focus_invalid_json`, `focus_request_failed`). Where the provider's catalog lists `structured_outputs`, focus requests use `json_schema` (strict for focus-only requests whose schema is closed and fully required, non-strict when combined with the general description), otherwise `json_object`; local validation applies either way. Focus answers are cached separately (`focus-answers/`, prompt `focus-v1`) under the unchanged description key plus the focus identity: one request fills both, a cached description gets a focus-only request, and both cached means no request. `--dry-run` reports `would_request` and focus counts; `--max-frames` counts frames needing a request (a corrective retry can add one per frame).
- `skywrite describe cache SOURCE [--model M] [--focus TEXT] [--kind frame|video|focus]` lists cached descriptions and focus answers for a source's content, grouped by kind, provider, model, prompt, cast and focus, with compact frame-time ranges, sizes and creation times; read-only. Cache entries now record listing metadata (older entries are annotated when next read).
- Bundled skill `describing`: when to use `describe frames`, `video`, `--focus` and `describe cache`.
- Agent skills, saved style prompts, task model defaults and `skywrite nit` feedback capture.
- Named model providers: `skywrite providers add NAME --base-url URL [--key-env VAR] [--header NAME=VALUE] [--timeout SECONDS]`, `list`, `show` and `remove` register OpenAI-compatible servers (local llama.cpp, Ollama, LM Studio, other hosts) beside the built-in `openrouter`, storing only the name of a key's environment variable. Model references are `PROVIDER:MODEL` (`local:qwen3:0.8b`) wherever a model is accepted; bare and `vendor/model:variant` IDs stay OpenRouter's. Analysis, frame and video descriptions, standard multipart transcription and edit suggestions can use any provider; generation stays on OpenRouter. Other providers never receive OpenRouter-only fields or keys, plain `http://` warns outside loopback and private networks, response caches key on the provider, an unreachable server fails once without retrying, `models list --provider NAME` lists a server's `/models` with unverified capabilities labeled, and `doctor` checks provider reachability.
- On-device transcription with NVIDIA Parakeet TDT 0.6B v3 through the built-in `ondevice` provider (`--model ondevice:parakeet-tdt-0.6b-v3`): runs in-process on transcribe.cpp/ggml (Metal on Apple silicon, CPU elsewhere), free, no key, audio stays on the computer. Its pinned 740 MB model is downloaded only by `skywrite models download` or `transcribe --download` (resumable, size-bounded, SHA-256-checked, re-verified before each use), listed with status and its CC BY 4.0 attribution by `models list --provider ondevice` and `models list --task transcription` (`ondevice_models`), and deleted by `models remove`. Transcripts keep every guarantee (real token word times, source-time shifting, low-audio flags, ordering, `usage.source_sha256`); chunk usage records engine, backend, threads and model hash at `cost: 0`. Scribe v2 stays the default; see the dated evaluation in docs/model-evaluation.md. Building from source now needs cmake and a C++ compiler unless `--no-default-features`; Linux release binaries stay static (built in Alpine) and x86_64 needs AVX2 for the on-device engine only.
- `review lint` warns about `unfinished_ending` (the edit's last heard dialogue has no sentence-final punctuation, the next source word continues the thought, or a counted list is left open, with the cut-off words and times) and `dead_air` (pauses between heard dialogue words longer than `--dead-air-seconds`, default 0.6, measured on the edited timeline; deliberate pauses are marked in the edit).
- Edit v1 has a top-level `pauses` list (`start`, `end`, optional `note`, timeline seconds; ordered, non-overlapping, inside the edit) for deliberate silences: `review lint` does not report them as `dead_air`, FCPXML and Premiere XML exports write them as `Pause` markers, Premiere XML import reads them back, and renderers ignore them.
- `verify --ends-together` (video and audio stream ends within `--end-tolerance`, default 0.05 s), `--loudness` (EBU R128 integrated loudness and true peak against `--target-lufs` -16 ±`--lufs-tolerance` 1 and `--max-true-peak` -1 dBTP, measured as `audio normalize` does), `--black` (`first_frame_black`, and black spans of at least `--black-min-seconds`, default 0.5) and `--frozen` (spans of at least `--frozen-min-seconds`, default 2), with `--edit EDIT.json` marking black inside the edit's own first fade-in or last fade-out and freezes inside its still-image clips as `allowed` (`--edit-tolerance`, default 0.1 s), with the measured values and times in `checks`, `stream_ends` in every decoded report, and a `not_measured` list. Filter output is parsed identically on FFmpeg 5.1.2 through 9.1. `--black` and `--frozen` run in their own video decode, because on FFmpeg 7.0 and 7.1 the detector branch of the counting decode made FFmpeg abort.
- `skywrite doctor` reports whether this FFmpeg has the `rubberband` filter (`audio_stretcher`) and the libass `subtitles` filter that burned-in captions need (`burned_captions`). When `subtitles` is missing it adds a `fix` hint: `ffmpeg-full` on macOS, or a distribution FFmpeg built with libass on Linux.
- Release binaries for Linux (static musl: x86_64, aarch64; no glibc requirement) and macOS (Apple silicon, Intel) on GitHub Releases, with SHA256SUMS, third-party license notices and signed GitHub build provenance attestations for every asset (`gh attestation verify <file> --repo FlyCockpit/skywrite`); archives include the embedded Geist font license as `fonts-OFL.txt`, and Linux archives include the statically linked musl libc's notice as `musl-COPYRIGHT.txt`.
- `external_sources` in every render and export result lists sources outside the edit file's directory; symlinked and special-file sources are refused, in edits and in imported XML. Edit and XML files are documented as trusted input.
