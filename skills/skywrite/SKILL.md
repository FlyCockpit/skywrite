---
name: skywrite
description: Understand local media, synchronize recordings with offset and drift, create validated assembly edits, and export or render them through the Rust Skywrite CLI.
---

Use installed `skywrite` (or the repository's `target/release/skywrite`). Start with `skywrite doctor` and `skywrite schema`. Successful commands return JSON. Progress/errors go to stderr and failures exit nonzero. Record ALL frustrations with `skywrite nit "description"`; when something cannot be decoded or verified, include the raw command output, the operator-confirmed settings, and the relevant source file from https://github.com/FlyCockpit/skywrite. Before creative choices (music, B-roll, pacing, color), read the user's saved preferences with `skywrite styles list`/`read`, and ask the user when none apply; do not invent taste rules or save styles on the user's behalf. Discover models with `skywrite models list --task TASK`; inspect capabilities/prices and use `--model`, task environment, or a saved task default. Never assume a current model ID or treat zero generic video prompt prices as free generation. If the user runs a local or other OpenAI-compatible model server, `skywrite providers list` shows it; select its models as `PROVIDER:MODEL` (for example `--model local:qwen3.5-0.8b`; list them with `skywrite models list --provider local`) for analysis, descriptions, transcription and edit suggestions. Generation stays on OpenRouter. Small local models describe less accurately: confirm important frames by viewing them.

1. Inspect sources: `skywrite inspect <files...>`. Understand durations, streams, frame rates, and audio availability. Phone footage stored landscape reports a video `rotation` (-90 or 90) and renders upright; Premiere XML exports fit each clip to the sequence by that displayed size, like the render (exact for square-pixel sources and quarter turns).
2. Sample visuals without a paid call: `skywrite analyze video.mp4 --local --frames 12 -o analysis.json`. Use your image viewer on the returned JPEG paths. Sparse samples do not reveal every event or exact shot boundary.
3. Get words: `skywrite transcribe source.mp4 -o transcript.json`. This explicitly sends bounded audio to the selected model provider (OpenRouter unless the model is `PROVIDER:MODEL`). Honor the user's API budget. For free, private transcription use `--model ondevice:parakeet-tdt-0.6b-v3` (runs on this computer; its 740 MB model must be downloaded once with `skywrite models download ondevice:parakeet-tdt-0.6b-v3` — ask the user before downloading; it keeps fewer fillers than the default). Cached exact requests reuse results; do not repeatedly disable the cache.
4. Request optional structured visual analysis: `skywrite analyze source.mp4 --model MODEL --transcript transcript.json --prompt 'Editorial intent' -o understood.json`.
5. Sync a separate recorder (or any second recording) to the camera: read `skywrite skills read synchronization` first. Measure: `skywrite sync --reference camera.mp4 --asset recorder.wav --method audio -o recorder.sync.json` (`--reference` is the camera on the timeline, `--asset` the recorder; one sync per camera file). For speech without shared sound, sync two `skywrite transcribe` outputs instead.
6. Place: put the camera clip on the timeline, then `skywrite sync apply --sync recorder.sync.json --edit edit.json -o edit.synced.json --verify`. It writes the recorder clip(s) on the frame grid with the drift `speed`, trims them to the real overlap, handles takes with a cut or recorder restart (`segments`), mutes the camera's own sound, validates, and with `--verify` renders and re-syncs each clip (`verify.passed`; clips under 15 s are skipped). Never compute the placement yourself. It refuses results that are not `strong` with drift estimated: then tell the user what was measured and record a nit; never place an ambiguous, failed or refused match. Check `uncovered` (camera time without recorder sound) and listen at the start, middle and end.
7. Write the edit JSON (version 1) from `skywrite schema`, using real sources and complete thoughts. Every clip has an explicit timeline `start`; video track 0 is the bottom layer and upper tracks (B-roll, titles) composite above it. Put continuous dialogue on the bottom track or an audio track, and mute B-roll sound with `"audio":{"volume":0}`. Carry the original transcript into analysis with `--transcript`; supplied transcripts must include `usage.source_sha256`, 64 hex digits (case-insensitive) matching the media content SHA-256; use original word starts/ends for audible cuts, never seconds guessed from summaries or uniformly sampled frames. Duration is OUTPUT seconds and source consumption is `duration*speed`. Stills have source_in 0 and speed 1. Use `volume_keyframes` and fades to ride music around dialogue, `opacity`/fades for pictures, `sources[].lut` for a log camera LUT, and `master.limiter_db` to cap the mix.
8. `skywrite edit validate edit.json` before exporting/rendering. Read frame-rounding warnings. Keep `source_in` word precision; round output duration outward enough to retain the final word after `duration*speed`. Clips on one track must not overlap. Muted B-roll and intentional J/L cuts can cross words visually while a separate dialogue track continues. `skywrite edit suggest --analysis understood.json --brief 'Intent' --model MODEL -o edit.json` can draft a validated edit, but you still judge its quality. Add repeatable `--transcript words.json` for existing analyses without words; unmatched or conflicting alignments fail. Review advisory audible word-cut warnings on stderr.
8a. Describe pictures with `skywrite describe frames SOURCE --every 30` (survey) and `--around TIME --window 1` (dense, around a candidate cut); results are cached per frame, so passes never pay twice. Use `--cast cast.json` (text appearance descriptions) for advisory who-is-visible hints, never as identification. `skywrite describe video SOURCE --start S --duration 8` reports timed gestures, expressions and shot changes. Rotated phone footage is described, sheeted and verified (`verify --expected-width/--expected-height`) by its displayed, upright size. When you need something specific from each frame (face boxes, a visible logo, sign text), add `--focus "what you need"` and, for an exact JSON shape, `--focus-schema schema.json` (subset and `"x-skywrite": "box"` in `skywrite describe frames --help`); read `focus.answer` in each frame. Coordinates are normalized 0..1 of the full upright frame, origin top-left, boxes `[x1, y1, x2, y2]` (left, top, right, bottom); they are model estimates, so view the frame before relying on one. Focus answers are cached apart from descriptions: a cached description is reused and only the focus is asked, so never leave out `--focus` to save money. `--dry-run` gives `would_request` (initial requests; a corrective retry can add one per frame) for the exact command, and `skywrite describe cache SOURCE` lists what is cached. A failed answer is a typed `focus.error`, and a valid result that could not be cached carries `cache_error`. Read `skywrite skills read describing` for the workflow.
8b. Focus in on cuts: around each candidate cut, `skywrite review sheet SOURCE --start S --duration 1 --every 2 -o sheet.jpg` shows consecutive exact frames with source times; view them before choosing B-roll or a cut frame. `skywrite review cuts edit.json --output-dir NEW_DIR` makes audition clips around every cut. Watch and listen to them; delivery and fit are your judgement, guided by the user's saved styles.
8c. You can't watch or hear the result: run the measured checks, quote the numbers, and say what was and wasn't measured. Before rendering, `skywrite review lint edit.json --transcript T.json` (silent visible speaker, repeated or clipped words, `unfinished_ending` when the dialogue stops mid-sentence or mid-list, `dead_air` pauses over 0.6 s, sound cut off, beds near dialogue, `brief_shot` flash frames between hard cuts (fades and dissolves are not checked yet, black gaps only between full-frame pictures; watch the shots in `checked.brief_shots_not_checked`); mark deliberate pauses in the edit's `pauses` list). After rendering, `skywrite verify out.mp4 --ends-together --loudness --black --frozen --edit edit.json` (picture and sound end within 50 ms; -16 ±1 LUFS and -1 dBTP true peak by default, `--target-lufs -14` for music streaming; black first frame and black spans of 0.5 s or more; frozen spans of 2 s or more; `--edit` allows its own fades and stills). Read `checks` and `not_measured`.
9. Render a low-resolution assembly using the edit canvas and `skywrite edit render edit.json -o preview.mp4`; inspect frames/listen to audio around cuts. Each clip is on screen for exactly its grid frames (from its start frame for its frame count, at any rate, after cuts and gaps, one-frame clips too), so a frame off at a cut is an edit problem, not rendering; each frame shows the source frame on screen at its source time (`source_in + n × speed / fps`), as in an NLE. Give tracks a `role` (dialogue, music, effects); to check dialogue by transcription under a music bed, render `--roles dialogue` and transcribe that. For clip speeds beyond 0.1%, check `audio_stretcher` in the result: `rubberband` keeps sound within about 6 ms (8 ms at 0.125x) of its position; if it fell back to `atempo` (warning), audio can land tens of ms early (up to about 60 ms below 0.5x), so avoid creative speed changes on lip-synced dialogue or use an FFmpeg with rubberband (`skywrite doctor` reports it). Any FFmpeg 5.1 or newer, 7.x included, renders black lead-ins before late-starting video and crossfaded `audio loop` beds alike ([validation](../../docs/validation.md#ffmpeg-version-compatibility)); a stretched pure tone after digital silence inside a clip can come out up to 15 dB low with rubberband, so check the level of sustained tones you slow down or speed up. Iterate the edit JSON, not original media.
10. Deliver `skywrite edit export edit.json --to premiere -o edit.xml` (Premiere Pro), `--to fcpxml -o edit.fcpxml`, `--to ffmpeg -o render.py`, or an optional `--to hyperframes|remotion -o NEW_PROJECT_DIRECTORY`. Optional composition runtimes are only required for those targets. You may extend generated projects with graphics/effects. Edit and imported XML files are trusted input like scripts: before sharing a render or project, check `external_sources` in the result, which lists every source outside the edit's directory (projects copy those files). Symlinked and special-file sources are refused; reference the real file.

Use `skywrite image render --file title.html -o title.png --width 1280 --height 720` for native still graphics using embedded upstream Takumi 2.20.0 and the bundled OFL Geist font. Use inline HTML style/tw attributes or upstream JSON nodes; local image paths resolve relative to the template. Register extra font files with repeated `--font PATH`. No Takumi executable is required. WebP/JPEG support `--quality`; PNG is lossless. Remote resources, SVG, stylesheet blocks, and JavaScript are unsupported. Then add the still to the edit.

Never overwrite an original media file. Existing outputs require `--overwrite`. Do not fabricate word timestamps or claim events outside the observed coverage. Model suggestions are candidate edits, not authoritative shot detection. Preserve source licenses/attribution in any shared fixture or deliverable. No ads capabilities are part of this CLI.

Use `skywrite styles` for reusable creative prompts and `skywrite skills` for procedural instructions. Read built-in workflows before using a new output tool. Shared content-addressed frame and exact contextual-request caches live in the XDG user cache; keep them enabled to avoid duplicate charges. `--cache-dir` overrides `SKYWRITE_CACHE_DIR`, then `XDG_CACHE_HOME/skywrite`, then `~/.cache/skywrite`. Media hashes live in `media-sha256-v1/`, keyed by canonical path and validated against size, mtime, ctime, device and inode; changes require rehashing. Files modified (mtime or ctime) in the last two seconds are hashed without caching. Deleting the cache is always safe. See `skywrite defaults` for task environment names. Native HTML graphics can use explicit cached Google Fonts with `--google-font FAMILY`; offline rendering uses `--offline`. Compose graphics into edits and inspect character/reference-frame capabilities before generation. Styles/skills are text references, never implicitly executed.

Generation: discover task models before spending. Start a character with `generate image`, reuse it with `--reference`, then animate using `generate video --first-frame` or `--last-frame`. H3 Max accepts one keyframe per request. Save the job ID and use `jobs resume JOB_ID --wait 60 --output video.mp4`. Generation exits 0 only for completed or still-running jobs; otherwise stderr has `error.code` and `error.job`. `not_sent` means the connection failed before anything was sent and nothing was billed: rerun the same command once (tell the user if it keeps failing; check network/proxy). Never automatically resubmit an uncertain job (`job_uncertain`); inspect OpenRouter activity. A new `--take` intentionally spends for a new variation. See [generation workflows](../../docs/generation.md).

AI video enlargement: `upscale video --source-job JOB_ID --model MODEL --factor 2`, or `--source-url` for your hosted HTTPS asset. OpenRouter currently does not accept local MP4 uploads directly; explicit `--upload` can bridge a configured public S3/R2 bucket (live compatibility unverified). `upscale image INPUT --factor 2 --output OUT.png` is non-AI Lanczos resizing. Do not call generative high-resolution editing faithful super-resolution. HTML graphics, generated stills, and video clips can all be combined in one edit.

Local MP4 upscaling may opt into a user-configured public S3/R2 bucket using `upscale video FILE --upload [--delete-upload-after]`. Never enable public access or upload implicitly. `storage upload FILE --dry-run` needs no cloud credentials; `storage purge --dry-run` makes read-only LIST/HEAD requests. See `docs/storage.md`; live bucket compatibility remains user-unverified. Purge selects only marked Skywrite hash objects and normally preserves active local jobs.

Setup: `skywrite init` adds missing offline starter preferences; `skywrite defaults TASK` reports the effective model and source, and `skywrite defaults TASK set MODEL` changes a saved choice. Environment overrides remain effective. Read [configuration](../../docs/configuration.md).

Narration/music: discover `speech-generation` voices or `music-generation` models, then use `generate speech --file script.txt --voice VOICE --model MODEL --output narration.mp3` or `generate music --prompt PROMPT --instrumental --model MODEL --output bed.mp3`. Use actual transcribed word timings for visual synchronization. Generated speech has dead digital-black pauses; when the user has a room-tone recording (their room with nobody talking), finish it with `skywrite audio roomtone narration.mp3 --bed room.wav -o narration-room.wav` (keeps the duration, so word timings still apply; `--bed-highpass 120` for hum). Without a recording, ASK THE USER before `skywrite audio record-bed --seconds 30 -o room.wav --confirm`: it captures their real room through their microphone (list devices with `skywrite audio inputs`). Tell them how: the room the voice should seem to be in, same microphone and gain, nobody talking or moving, notifications off, 30 s. Act on its warnings (re-record, or `--bed-highpass 120`). To dip music under narration, `skywrite audio duck bed.mp3 --sidechain narration.mp3 -o bed-ducked.wav` (use `narration-room.wav` instead once you have made it; same samples on every run; a mono bed becomes stereo at -3 dB per channel; measure the dip, you cannot hear it). Read `skywrite skills read technical-explainer` and [audio generation](../../docs/audio-generation.md). These are decoded waveform assets, not MIDI. Never assume zero generic music token prices mean a free song. Completed jobs replay without another paid submission. Share deliverables through `outputs upload/list/download`; see [shared outputs](../../docs/outputs.md).

Transcript identity: `analyze --transcript`, `edit suggest`, `describe frames --transcript`, `review lint --transcript` and edit caption tracks using `from_transcripts` require `usage.source_sha256` matching the media bytes. Byte-identical copies are accepted. Verify before model requests and, where practical, before other expensive work. Missing, invalid or mismatched fingerprints fail; re-run `skywrite transcribe` on the media, or point the transcript/edit at the media it was made from. A transcript `.json` caption `source` (placed by explicit offset/scale), standalone `captions convert` and `sync --method transcript` do not bind transcripts to media and do not require fingerprints.

Captions: deliver SRT by default so the user can edit wording, timing and style in their NLE. Burn captions into pixels or render caption images only when the user explicitly asks; burning needs `burned_captions.subtitles_filter_available` in `skywrite doctor`, and its `fix` hint says how to get libass. For Premiere, deliver the XML and its SRT together and tell the user to import both.

Dialogue timing: read `skywrite skills read synchronization` for source-time conventions and bounded word lookup. `analyze --local --transcript transcript.json --start SECONDS --duration SECONDS` attaches existing words without an ASR call. Edit suggestions recheck source fingerprints and receive only words overlapping each analyzed range; words crossing a range boundary retain their actual starts/ends. Narrow ranges when the word context limit is exceeded. Listen around every dialogue cut; provider timestamps are alignment evidence, not a guarantee of perfect phoneme boundaries. Missing words do not prove silence. No automatic paid retakes.
